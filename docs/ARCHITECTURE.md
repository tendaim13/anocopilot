# Ano architecture

Ano is a standalone, tenant-safe, chat-first AI sales research and planning product. Mercury is a future connector—not a shared backend, internal import, or database dependency.

```text
Browser client (Material Web 2.4.1 + React 19 Client Components)
  -> Next 16 Proxy refreshes the Supabase session
  -> Thin /api/v1 route validates input and idempotency keys
  -> Workspace session resolves authenticated user, membership, and domain policy
  -> Domain service orchestrates research / synthesis / queue transitions
  -> LangGraph JS (Postgres checkpointer in ano_langgraph) manages resumable interrupts
  -> Server-only Bedrock adapters interpret, plan, and synthesize saved excerpts only
  -> Ano-owned persistence records conversations, messages, plans, sources, claims, receipts, and audit logs
  -> Controlled providers (private SearXNG, OpenStreetMap Nominatim/Overpass, bounded Prospeo, selective Dropcontact & approval-gated Outreach/Mercury)
```

## Schema groups

| Group | Tables | Purpose |
| --- | --- | --- |
| Identity | `workspaces`, `workspace_domains`, `workspace_members`, `workspace_invites` (plus `create_ano_workspace`, `ensure_personal_ano_workspace`, `preview_workspace_invite`, `accept_workspace_invite` RPCs) | Multi-workspace tenancy, roles, email-domain allow-lists, and admin-only SHA-256 hashed team invite links (`role in ('admin','member','viewer')`) with automatic personal-workspace provisioning when an invited user joins a team workspace. |
| Conversations & Graphs | `ano_conversations`, `ano_graph_runs`, `ano_graph_checkpoints`, `ano_messages`, `ano_graph_decisions`, `run_events` (plus `ano_langgraph.*`) | Durable chat history, LangGraph thread state, interrupts, checkpoints, and timeline events. |
| Phase A Planning & Product Intake | `research_briefs`, `research_questions`, `research_plans`, `conversation_product_sources` | Structured offers, 2-question intake metadata (`business_location`, `target_markets_json`, `intake_complete`), multi-format product source extracts (`website_url`, `pdf`, `docx`, `txt` via `POST /api/v1/conversations/[conversationId]/product-sources`), and versioned research plans (`plan_approval_mode`: `manual` \| `autopilot`). |
| Autopilot Orchestration | `autopilot_runs` | Checkpointed 6-stage pipeline state (`brief_and_plan` -> `market_research` -> `synthesis_and_lock` -> `company_discovery` -> `people_and_emails` -> `outreach_templates` -> `done`), atomic stage leases (`stage_lease_token`), partial-failure warnings, sequential client stepper in `research-conversation-workbench.tsx`, calm progress + quick jump navigation (`AutopilotProgressCard`, `ResultsJumpBar`), resumable stepping via `POST /api/v1/conversations/[conversationId]/autopilot/{start,step,cancel}` (`vercel.json` `maxDuration: 300`), and post-autopilot freeform reference chat & targeted partial re-runs (`scheduleAutopilotPartialRerun` / `recordAutopilotStageSummary` across affected downstream scopes such as Stages `4 -> 5 -> 6`, `4 -> 5`, `5`, or `6` only). |
| Phase B Evidence | `ano_research_runs`, `provider_action_requests`, `research_waves`, `research_queries`, `research_search_results`, `research_sources`, `research_source_assessments` | Bounded SearXNG searches, SSRF-safe source excerpts, hashes, receipts, and quality scores. |
| Phase C Synthesis | `ano_research_syntheses`, `research_claims`, `market_profiles`, `industry_profiles`, `target_decisions` | Citation-audited observations, comparable evidence, inferences, market/industry profiles, and locked target route. |
| Phase D Account Discovery | `provider_company_searches`, `account_candidates` (plus `provider_action_requests` audit rows) | Dual-source OpenStreetMap/Prospeo discovery, 1-click free OpenStreetMap runs, interactive cohort artifact table/drawer, two-way grounded chat filter refinements (`conversation-chat-model.ts`), structured `signals_json`, fit scores, and `claim_ids` separated from industry claims. |
| Phase E People & Playbooks | `provider_person_searches`, `contact_candidates`, `contact_verification_runs`, `account_playbooks` | Product-aware Buying Committee criteria (archetype, seniority, department, title include/exclude), dual-source people discovery (`website_team` \$0 crawl with free `public_website` email/phone capture separating `direct_public` person emails from `shared_inbox` addresses + fixed Prospeo `/search-person`), interactive People Cohort artifact drawer, multi-provider selective email verification (`prospeo` `/bulk-enrich-person` or `dropcontact` `/batch`, re-runnable across additional batches), and factual evidence-backed account playbooks. |
| Phase F Outreach & Accountability | `outreach_template_packs`, `outreach_drafts`, `proposals`, `approval_decisions`, `audit_logs`, `notifications` | Blaster-ready human-voice 3-step email sequences (anti-AI linter enforcing 60/50/30 word caps, zero dashes/exclamation marks/AI clichés, lowercase subjects, no Email 1 URLs, standard merge variables, single bounded LLM rewrite pass, `$0` external spend, and chat `templateUpdate` refinements), 1-click RFC-4180 formula-safe CSV/Markdown export pack (`LeadExportCard`, `/api/v1/conversations/[conversationId]/export`, `/api/v1/people/export`, `/people` directory export), plus versioned multi-channel drafts with deterministic eligibility checks, immutable per-action human decisions, Mercury proposal receipts, and append-only audit trail (`leads.exported_csv`, `templates.exported`). |
| Internal Usage Ledger | `ano_internal.api_usage_logs` (write-only `public.record_internal_api_usage` & boolean `public.check_internal_usage_budget` RPCs) | Private operator-only telemetry ledger capturing provider calls, LLM tokens, Prospeo/Dropcontact credits, remaining balances, and estimated USD cost. Revoked from `public`/`anon`/`authenticated`, unexposed in PostgREST, and excluded from all `/api/v1/*` routes and UI; readable solely via `npm run usage:report` using local `SUPABASE_DB_URL`. |

Every table is protected by RLS. A signed-in member can belong to one or more workspaces (switching the active tenant via `ano_active_workspace_id` across verified memberships) and can only read their workspace. Joining an existing workspace is restricted strictly to admin/owner-issued single- or bounded-use hashed invite links in `workspace_invites` (`is_ano_workspace_admin`), while owners/admins/members can write approved Ano records (`viewer` is read-only). `audit_logs` allows select/insert only—no client update or delete policy.

## Database operation

Schema migrations live in `supabase/migrations/` (`000001` through `000027`). The application's runtime never uses a service-role key for DDL. To apply or verify migrations against Ano's dedicated database, set `SUPABASE_DB_URL` and `ANO_DATABASE_LABEL=ano` in `.env.local` and run:

```bash
npm run db:apply
npm run db:status
npm run usage:report -- --days=30
```

## CI/CD & Vercel deployment

GitHub Actions workflows in `.github/workflows/ci.yml` and `.github/workflows/deploy-production.yml` run Node `22.x` across a single cost-capped CI job (`check:migrations`, `typecheck`, unified offline `npm test`, and `next build`) followed on `main` by `production`-environment Supabase DDL migration checks (`db:apply:ci` / `db:status:ci`), prebuilt Vercel CLI deployment (`vercel.json` Fluid Compute up to `300s`), and post-deploy smoke checks against `GET /api/health` and `GET /api/v1/conversations`. Setup and required GitHub/Vercel secrets are documented in [docs/CI_CD_SETUP.md](file:///Users/tendaimidzi/Code/AnoCopilot/docs/CI_CD_SETUP.md).
